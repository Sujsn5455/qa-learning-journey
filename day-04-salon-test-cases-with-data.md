\# Day 4 — Bug Report Writing



\## What is a Bug?

A bug is a defect or error in software that causes it to behave differently from expected.



\## What is a Bug Report?

A bug report is a document that describes a defect clearly so developers can reproduce and fix it.



\## Why Bug Reports Matter

\- Developers can reproduce the issue

\- No back-and-forth questions

\- Bugs get fixed faster

\- Creates a trackable history



\## Bug Report Template — Columns



| Field | What to Write |

|-------|---------------|

| Bug ID | Unique identifier (BUG\_001) |

| Title | Short and specific summary |

| Module | Which part of app |

| Environment | Browser, OS, device, build |

| Steps to Reproduce | Numbered steps |

| Expected Result | What should have happened |

| Actual Result | What actually happened |

| Severity | Critical / High / Medium / Low |

| Priority | P1 / P2 / P3 / P4 |

| Status | New / Open / Fixed / Closed |

| Attachments | Screenshot or recording |

| Reported By | Your name |

| Reported Date | Today's date |



\## Severity vs Priority



\### Severity

How much damage the bug causes.

\- Critical: App crashes, data loss

\- High: Major feature broken

\- Medium: Feature works but not fully

\- Low: Cosmetic issue



\### Priority

How urgently it needs to be fixed.

\- P1: Fix immediately

\- P2: Fix in current sprint

\- P3: Fix soon

\- P4: Fix whenever possible



\## Good vs Bad Bug Title



\### Bad Title

"Login not working"



\### Good Title

"Login fails with 401 error on Chrome when entering valid credentials"



\## Tips for Writing Bug Reports

1\. Title must be specific

2\. Steps must be reproducible

3\. Expected result must be clear

4\. Actual result must be exact

5\. Attach screenshot or video

6\. Use simple language

7\. Do not combine multiple bugs in one report



\## Key Takeaway

A bug report is a communication tool. Write it so a developer can reproduce the bug without asking you any questions.
