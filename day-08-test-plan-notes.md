\# Day 8 — Test Plan Document



\## What is a Test Plan?

A Test Plan is a document that describes what will be tested, how, by whom, and when.



\## Why Test Plans Matter

\- Structure for testing

\- Everyone knows the goal

\- Measurable progress

\- Risks are managed

\- Stakeholder confidence



\## Sections of a Test Plan (14)

1\. Test Plan ID

2\. Introduction

3\. Scope

4\. Objectives

5\. Test Strategy

6\. Test Environment

7\. Entry Criteria

8\. Exit Criteria

9\. Test Deliverables

10\. Roles and Responsibilities

11\. Schedule

12\. Risks and Mitigation

13\. Tools

14\. Approvals



\## Entry vs Exit Criteria



\### Entry Criteria (Start)

\- Requirements approved

\- Test cases written

\- Test environment ready

\- Test data prepared



\### Exit Criteria (Stop)

\- All test cases executed

\- No critical bugs open

\- 95% pass rate

\- Test summary report written



\## Testing Types

Unit, Integration, System, Smoke, Regression, UAT



\## Test Deliverables

Plan, Cases, Bugs, Summary, Metrics



\## Tools

Jira, Postman, Git, Chrome DevTools, MySQL, Playwright



\## Key Takeaway

A Test Plan is the roadmap of testing. Write it before testing starts.
