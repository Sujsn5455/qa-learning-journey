\# Day 7 — Agile \& Scrum



\## What is Agile?



Agile is a mindset for software development. It focuses on:



\- Individuals and interactions over processes and tools

\- Working software over comprehensive documentation

\- Customer collaboration over contract negotiation

\- Responding to change over following a plan



Agile was created because Waterfall was too slow. Clients waited months for software. By delivery time, requirements had changed.



\## What is Scrum?



Scrum is the most popular Agile framework. Work is organized into short cycles called sprints.



Sprint duration: 1 to 4 weeks.

At the end of each sprint, working software is delivered.



\## The Three Scrum Roles



\### 1. Product Owner (PO)

\- Decides what to build

\- Owns the Product Backlog

\- Prioritizes features

\- Represents the customer



\### 2. Scrum Master (SM)

\- Facilitates the process

\- Removes blockers

\- Coaches the team

\- Servant leader, not a manager



\### 3. Development Team

\- Developers, testers, designers

\- Builds the product

\- Cross-functional and self-organizing

\- QA is part of this team



\## The Four Scrum Ceremonies



\### 1. Sprint Planning (start of sprint)

\- Team decides what to build

\- PO explains highest priority items

\- Team estimates effort

\- QA asks clarifying questions about acceptance criteria



\### 2. Daily Standup (every day, 15 minutes)

Each person answers three questions:

1\. What did I do yesterday?

2\. What will I do today?

3\. Are there any blockers?



QA reports test progress and blockers.



\### 3. Sprint Review (end of sprint)

\- Team demos working software

\- PO accepts or rejects

\- QA confirms features are tested



\### 4. Sprint Retrospective (after review)

\- Team reflects on the sprint

\- What went well?

\- What went wrong?

\- What will we improve next sprint?



\## Key Agile Terms



| Term | Meaning |

|------|---------|

| User Story | Feature from user's perspective |

| Acceptance Criteria | Conditions for story to be done |

| Product Backlog | All features, prioritized by PO |

| Sprint Backlog | Subset for current sprint |

| Story Points | Effort estimate (1, 2, 3, 5, 8, 13) |

| Velocity | Story points completed per sprint |

| Definition of Done | Checklist for what "done" means |

| Burndown Chart | Visual of work remaining |



\## User Story Format



As a \[type of user],

I want \[some action],

So that \[some benefit].



\### Salon Example



As a customer,

I want to book an appointment online,

So that I don't have to call the salon.



Acceptance Criteria:

1\. User can select a service

2\. User can select a date and time

3\. User can select a stylist

4\. Booking is confirmed with a unique ID

5\. Confirmation email is sent

6\. Booking appears in My Bookings



\## QA's Role in Agile



QA is not a separate team. QA is part of the Development Team from Day 1.



QA responsibilities in each ceremony:



\- Sprint Planning: Review acceptance criteria, ask testability questions

\- Daily Standup: Report testing progress, raise blockers

\- Sprint Review: Confirm features are tested

\- Retrospective: Suggest process improvements



QA writes test cases early, based on user stories. Testers start work before code is written.



\## Agile vs Waterfall



| Waterfall | Agile |

|-----------|-------|

| Sequential phases | Iterative sprints |

| Testing at the end | Testing throughout |

| Client sees product at end | Client sees product every sprint |

| Change is expensive | Change is expected |

| Big documentation | Light documentation |



\## Key Takeaway



Agile is a mindset. Scrum is a framework. Sprints are short cycles. QA is part of the team from Day 1, not a separate phase at the end.
